# Phase 5 手动验证用例（自定义正则 + ReDoS 防护 + 导入导出）

前置：`npm run build` → 加载 `dist/`；`npm test` 88 项断言全过。

## Case 1：添加自定义规则

1. 新建自定义档案（「＋」）→ 点 ⚙ 打开设置
2. 「自定义正则」区点「＋ 添加」
3. 名称：`工号`，正则：`EMP-\d{6}`，类型：身份证，置信度：高置信 → 添加规则

**期望**：
- 规则出现在列表中（含名称/类型/正则预览），复选框为启用
- 保存后粘贴：`员工 EMP-123456 和 EMP-999999 已登记`
- 两个工号都检出，类型显示「身份证」（自定义规则的归类），脱敏输出 `<<身份证号>>` / `<<身份证号:2>>`

## Case 2：ReDoS 防护 —— 嵌套量词拒绝

1. 添加规则，正则依次输入：`(a+)+`、`([a-z]+)+x`、`(unclosed`

**期望**：三种都**无法添加**，表单下方显示红字：
- `(a+)+` → "模式存在嵌套量词…可能导致灾难性回溯"
- `(unclosed` → "正则语法错误：…"

再输入安全模式 `(VIP|SVIP)-[A-Z]{4}` → 可正常添加（交替组+量词是安全的）。

## Case 3：规则停用与删除

1. Case 1 的规则取消勾选 → 保存 → 粘贴同样文本
2. 重新勾选；再删除规则

**期望**：停用后工号不检出；重新启用后恢复；删除后列表为空且不再检出。

## Case 4：自定义规则走完整管线

1. 添加规则 `ORD\d{8}`，类型：API 密钥
2. 粘贴：
```
订单 ORD12345678 已创建
备注 ORD12345678 重复出现
```

**期望**：两处都检出且**共享同一占位符**（同值规则 + 值传播管线对自定义规则同样生效）；将该值加入白名单后两处都不再检出。

## Case 5：导出

1. 有 ≥1 个自定义档案时，在档案设置底部点「导出档案 JSON」
2. 检查剪贴板内容

**期望**：提示"已复制到剪贴板"；JSON 含 `version: 1`、`exportedAt`、`profiles` 数组，每个档案含全部字段（whitelist/customRules/glinerLabels 等）。内置档案不在其中。

## Case 6：导入

1. 修改剪贴板为 Case 5 导出的 JSON（或故意改名）
2. 在另一个环境（或删掉原档案后）点「从剪贴板导入」

**期望**：
- 提示"成功导入 N 个档案（重名已自动加序号）"
- 新 Tab 出现，配置（白名单/自定义规则/灵敏度）与导出前一致
- 重名时自动变为「原名 2」

## Case 7：坏 JSON 与恶意导入

依次把以下内容放入剪贴板后点导入：

| 剪贴板内容 | 期望提示 |
|-----------|---------|
| `not json` | JSON 解析失败，请检查内容格式 |
| `{"version":99,"profiles":[]}` | 不支持的导出版本 |
| `{"version":1,"profiles":[]}` | JSON 中没有档案数据 |
| `{"version":1,"profiles":[{"id":"user-x","name":"恶意","customRules":[{"id":"r","name":"evil","pattern":"(a+)+","type":"HIGH_ENTROPY","confidence":"high","enabled":true}]}]}` | **导入成功**，但该档案的自定义规则列表为空（危险正则被 sanitize 过滤） |

## Case 8：无自定义档案时的导出

只有内置档案时点「导出档案 JSON」

**期望**：提示"没有可导出的自定义档案（内置档案无需导出）"，不写剪贴板。

## Case 9：内置档案回归

在「不限/通用文本/代码开发」下粘贴 Phase 1-2 的既有用例文本（env/连接串/PII 混排）。

**期望**：行为与 Phase 4 完全一致（自定义规则代码路径只在 `profile.customRules` 非空时执行，内置档案恒为空）。

## 已知限制

1. 时间预算（50ms/条）在单次 exec 卡死时无法中断（JS 正则不可抢占）——静态嵌套量词检查是主要防线，运行时预算是兜底
2. 导出不包含内置档案（导入后仍是自定义档案，避免覆盖内置语义）
3. 自定义规则单档案上限 50 条、正则长度上限 200 字符、匹配上限 200 处
4. 导入导出走剪贴板，无文件 IO
