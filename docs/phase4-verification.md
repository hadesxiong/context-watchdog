# Phase 4 手动验证用例（自定义档案）

前置：`npm run build` → `chrome://extensions/` 加载 `dist/`；`npm test` 66 项断言全过。

## Case 1：新建自定义档案

1. 打开 sidepanel，当前在「不限」Tab
2. 点击 Tab 栏右侧「＋」

**期望**：
- 新 Tab「自定义 1」出现并自动激活（高亮）
- 描述文案显示"基于「不限」的自定义档案"
- ⚙ 编辑按钮出现（内置档案 Tab 下不显示）

## Case 2：编辑类别开关与灵敏度

1. 在「自定义 1」下点 ⚙ 打开设置面板
2. 取消勾选「个人信息」，高熵灵敏度切「宽松」，保存

**期望**：
- 保存后面板收起，Tab 描述不变（名称未改）
- 粘贴：`我的手机号 13812345678\nAPI_KEY=Zx9Kq2LmN4Rt7Vw1Yb3Hd\n裸串 Xk9pQm2Zr7Tb4Wn8Yc3Hd5Jf 结束`
- **手机号不检出**（PII 类别已关）；env 键值与 22 字符裸串均检出（宽松档 20 字符）

## Case 3：分类型默认策略

1. 设置面板中把「高熵串」默认策略改为「保留」，保存
2. 粘贴：`裸串 Xk9pQm2Zr7Tb4Wn8Yc3Hd5JfGq1 结束`

**期望**：裸串出现在检出列表，但开关默认为**保留**；脱敏预览中保持原文。

## Case 4：值白名单

1. 设置面板白名单文本框输入两行：`example.com` 和 `13812345678`，保存
2. 粘贴：
```
API_KEY=Zx9Kq2LmN4Rt7Vw1Yb3Hd
手机号 13812345678 和备用 13998765432
邮箱 support@example.com
```

**期望**：
- `13812345678` 不检出，`13998765432` 检出（白名单是精确匹配）
- `support@example.com` 仍检出（白名单 `example.com` 是子串不放行）
- `Zx9Kq2...` 检出

## Case 5：白名单传播覆盖

1. 清空白名单，输入 `Tr0ub4dor&3x!`，保存
2. 粘贴：
```
DB_PASSWORD=Tr0ub4dor&3x!
再说一次 Tr0ub4dor&3x!
```

**期望**：两处都不检出（白名单在值传播后过滤，所有出现一并移除）。

## Case 6：持久化与记忆

1. 保持自定义档案激活，关闭 sidepanel 再打开
2. 检查 Tab 停留与白名单内容

**期望**：Tab 停在「自定义 1」；点 ⚙ 打开面板，白名单仍显示 `Tr0ub4dor&3x!`。

## Case 7：删除回落

1. 点 ⚙ →「删除档案」→ 确认

**期望**：「自定义 1」Tab 消失，自动回落到「不限」；重新打开 sidepanel 不再出现该档案。

## Case 8：内置档案保护

**期望**：在「不限/通用文本/代码开发」三个 Tab 下，⚙ 编辑与「＋」之外没有任何改删入口；「＋」在任意内置 Tab 下都能克隆新建。

## Case 9：Phase 4 修复回归（env 行内吞值）

粘贴（任意内置 Tab）：
```
API_KEY=Zx9Kq2LmN4Rt7Vw1Yb3Hd 与 support@example.com 沟通
DB_PASSWORD="my secret pass 123"
```

**期望**：
- 第一行：`Zx9Kq2...` 检出为「密码」，`support@example.com` 检出为**「邮箱」**（此前被错标为密码/吞值）
- 第二行：`my secret pass 123`（含空格引号值）整体检出为「密码」

## 已知限制

1. 白名单是**值级精确匹配**，不支持通配符/正则（Phase 5）
2. GLiNER 标签集修改只影响模型级联路径，模型未加载时无可见差异
3. 自定义档案数量未设上限，建议 ≤ 10 个
4. 「＋」新建基于当前激活档案——要基于「代码开发」新建需先切到该 Tab
