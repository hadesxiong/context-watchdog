# Phase 2 验证用例

对应改动：Profile 层（Tab 场景切换）、PII 规则集、YAML/JSON 降级覆盖、场景启发式（移除 MobileBERT）、GLiNER 级联、语义化中文占位符、依赖收敛。

验证方式：`npm run build` → 加载 `dist/` → 逐个用例粘贴核对。Tab 在输入框上方（不限 / 通用文本 / 代码开发）。

---

## 1. Tab 场景切换

### Case 1.1 Tab 基本行为

**操作**：切换三个 Tab，观察输入框下方的描述文案变化；刷新页面后确认停留在上次选择。

**期望**：
- 三个 Tab：不限（默认）/ 通用文本 / 代码开发
- 每个 Tab 有对应描述（悬停 title 也有）
- 选择被记忆（chrome.storage.local 持久化）
- 已有检测结果时切换 Tab 会自动重新检测

### Case 1.2 灵敏度档位差异

```
token value is Xk9pQm2Zr7Tb4Wn8Yc3Hd5Jf here
```

**期望**：
- 「代码开发」（loose 档）：检出该 22 字符高熵串
- 「通用文本」（strict 档）：不检出（阈值 30 字符）

### Case 1.3 置信度分层（universal 档）

```
服务器 192.168.1.1 和 京A12345 车辆登记
```

**期望**：「不限」模式下 IP/车牌被识别，但因中置信度默认动作为「保留」（开关显示保留），高置信度项（如手机号）默认替换。

## 2. PII 检测

### Case 2.1 手机号与座机

```
我的手机号 13812345678，公司座机 010-87654321，国际格式 +86 13912345678
```

**期望**：3 个号码全部识别为「手机号」类型，默认替换为 `<<手机号>>` / `<<手机号:2>>` 等。

### Case 2.2 身份证（校验位验证）

```
身份证号 11010519491231002X，错误示例 110105194912310021
```

**期望**：只识别 `11010519491231002X`（合法校验位），`...021` 不识别。

### Case 2.3 银行卡（Luhn 校验）

```
卡号 4532015112830366 和 4532015112830367
```

**期望**：只识别 `...366`（Luhn 通过），`...367` 不识别。

### Case 2.4 IP 与车牌

```
服务器 192.168.1.1 分配给 京A12345
```

**期望**：IP 和车牌都识别；「不限/通用文本」模式下默认保留，「代码开发」模式下也保留。

## 3. YAML / JSON 降级覆盖（模型不可用也能检出）

### Case 3.1 YAML 配置

```yaml
services:
  db:
    environment:
      db_password: Hunter2@Prod
      db_port: 5432
```

**期望**：`Hunter2@Prod` 检出为「密码」，`5432` 不检出；预览为 `db_password: <<密码>>`，结构完好。

### Case 3.2 JSON 配置

```json
{
  "api_key": "sk-proj-Zx9Kq2LmN4Rt7Vw1Yb3Hd5Jf8Gc6Sa",
  "timeout": 30
}
```

**期望**：api_key 检出并替换，timeout 不检出。

## 4. 语义化中文占位符

### Case 4.1 占位符样式

```
联系 13812345678 或邮箱 test@example.com，身份证 11010519491231002X
```

**期望**：
- 脱敏预览中的占位符为 `<<手机号>>`、`<<身份证号>>`（邮箱默认保留不替换）
- 同类多条时 `<<手机号:2>>` 序号递增
- 首条不带序号，便于阅读
